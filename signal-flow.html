Direct to responsible manager — not the intelligence pipeline
A failed control verification is not an observation and not an incident — it's an operational gap that requires immediate action. Routes directly to the manager responsible for that control at that site. They confirm rectification. Only if not rectified within SLA does it escalate to safety manager and enter the intelligence pipeline.
→ Rectified: logged as verification event, control assurance record updated. Not rectified within SLA → escalates to insight pipeline as at_risk_condition.
Intelligence Pipeline — what happens once a signal enters
01 — Prioritise
Safety Manager reviews AI draft. Endorses for action. Critical observations arrive pre-populated with AI narrative. Endorsement adds human weight — or (proposed) auto-endorses for critical signals.
02 — Learn
Enquiry dispatched to supervisors. Live synthesis updates as responses arrive. Toolbox talk generated and approved. FW Map® classification runs on insight + investigation. Communities thread seeded.
03 — Improve
Corrective actions assigned and tracked. Actions created from enquiry findings. Named lead assigned. Progress visible on insight card and in manager workspace.
04 — Resolved
All actions complete. Endorsers notified. Archived for 45 days. FW Map® classification data persists and feeds capacity analytics. Evidence trail complete.
Insight Classes — how signals generate intelligence
Standard Insight
Critical Insight — trend threshold crossed
Generated when near-miss count by work_type × org_level × time_window crosses a configurable threshold. Requires safety manager endorsement before moving through pipeline. The normal path.
Critical Cluster — proposed naming
Pattern Insight — accelerated threshold
Same mechanism as Standard Insight but threshold crossed faster — same signal type, multiple sites, compressed timeframe. Proposed: arrives with higher urgency flag, reduced endorsement friction, pre-populated notification to division manager not just site.
Solo Critical Insight
Single-event Intelligence — no accumulation
Generated by a single critical observation (barrier_failure or unwanted_energy_event with signal_type_confidence ≥ 0.70) or a critical incident (solo_critical trigger). Bypasses trend detection entirely. Requires safety manager review before moving through the pipeline.
✦ Design Notes — additions not yet in spec
Pre-endorsed critical observations — A barrier_failure with catastrophic energy release potential currently requires human endorsement before the intelligence pipeline can act. Proposal: auto-endorse when energy_release_potential = catastrophic, with immediate notification to safety manager. The human still reviews — but the pipeline doesn't wait for them. This is the same logic as why emergency services don't wait for approval to respond.

Control verification escalation path — A failed control check that isn't rectified within SLA is currently undefined in the spec. Proposal: after SLA breach, create an at_risk_condition observation automatically and inject it into the pool. This closes the loop between V5 control verification and the intelligence pipeline without requiring a separate escalation model.
