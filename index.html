Global References Tier 1 — cross-cutting definitions, not owned by any single feature
Taxonomies, classification frameworks, and rules consumed by multiple features. These files contain definitions only — never prompt text. Feature specs reference these by name; they do not copy the content. If a definition appears in more than one place, this folder is the authority.
  • globglobals/fw-map-blueprint.mdForge Works Map® — 15 factors, 3 domains, 3 maturity levels, per-factor classification guidance. Injected at runtime into fw_classify.
  • globglobals/signal-type-taxonomy.md5 signal types (positive_performance → barrier_failure), definitions, and pipeline routing rules
  • globglobals/energy-type-taxonomy.md8 energy types — kinetic through noise_vibration — with definitions and energy_release_potential scale (catastrophic → none, AI-derived by observation.enrich)
  • globglobals/barrier-assessment-values.md5 barrier states (absent → held) — definitions and classification guidance
  • globglobals/fw-classify-job.mdfw_classify job spec — base system prompt, all 3 user prompt variants (insight/investigation/enquiry), output schema, validation, triggering conditions. Canonical source for all FW classification runs.
  • globglobals/ai-output-standards.mdJSON-only output rules, rationale standard, suggestion language, confidence thresholds — applies to all prompts
  • globglobals/anonymisation-rules.mdPII handling — what to flag, how to scrub for downstream prompts — applies to all prompts that reference observation text
Feature Specs Tier 2 — canonical prompt text and complete pipeline specs per feature
One file per feature. Each file owns the complete pipeline for that feature in sequential order: capture → API → job → prompt → output → downstream effects. This is where canonical prompt text lives. Simulators and the prompt lab load from here — they do not contain their own copies of any prompt.
DRY rule: if you need to read or modify a prompt, come here. Do not edit the prompt text in a simulator or the prompt lab — those are consumers, not sources.
  • featfeatures/OBSERVATION-CAPTURE.mdCapture conversation (P6), enrichment (P1), context request (P2) — used by capture-sim.html and capture-sim-offline.html
  • featfeatures/INCIDENT-CAPTURE.mdIncident capture (P7), auto triage (P8) — used by capture-sim.html
  • featfeatures/CRITICAL-INSIGHT.mdInsight draft generation (P3), FW classification insight path (P10) — used by workflow-sim.html and observation-to-insight.html
  • featfeatures/INVESTIGATION.mdInvestigation assist (P4), toolbox narrative (P5), FW classification investigation path (P10) — used by workflow-sim.html
  • featfeatures/TOOLBOX-TALK.mdFull toolbox talk assembly (P6 of talks), content selection algorithm — used by workflow-sim.html
  • featfeatures/ENQUIRY.mdQuestion generation (P7), live synthesis (P8), final summary (P9), FW classification enquiry path (P10) — used by enquiry-sim.html
  • featfeatures/MANAGEMENT-SYSTEM-INGESTION.mdDocument ingestion AI prompt, requirement extraction schema — used by management-system.html
  • featfeatures/VISIT-BRIEFING.mdVisit briefing pack generation (P13), focus area prompts — no sim yet

Simulators Test harnesses — load prompts from specs/features/, contain no canonical content
Each simulator exercises a feature pipeline end-to-end. Prompts are injected from the relevant feature spec — the sim is the harness, the feature file is the source. Requires an Anthropic API key for live AI calls.
  • wetcapture-sim.htmlWet sim — non-authoritative. Capture sim — observation, incident, auto triage. Predates the Live Sim class. Superseded by observation-to-insight.html. Do not use as spec reference.
  • wetcapture-sim-offline.htmlWet sim — non-authoritative. 4 capture states incl. offline + API unavailable. Hardcoded fallback prompts not in any spec. Offline behaviour will move into observation-to-insight.html as a capability gate. Do not use as spec reference.
  • wetenquiry-sim.htmlWet sim — non-authoritative. Scripted demo of 3 enquiry triggers. No live AI. Superseded by insight-to-pull.html (to build). Do not use as spec reference.
  • wetworkflow-sim.htmlWet sim — non-authoritative. Scripted demo of 3 end-to-end scenarios. No live AI. Superseded by insight-to-broadcast, incident-to-investigation, and systemic-causes Live Sims (to build). Do not use as spec reference.
  • liveobservation-to-insight.htmlLive Sim — observation capture → enrichment → routing → critical insight → human review → FW classify. Live AI, prompts and references fetched from spec at runtime, REFS strip per stage shows injection level + role. State: working · Workspace: core. Stream catalogue: specs/MODEL-MAP.md
  • liveincident-to-investigation.htmlLive Sim — incident capture → triage algorithm → investigation assist → close gate → toolbox narrative + FW classify. Live AI for capture / assist / narrative / classify; triage runs synchronously as JS. Solo-critical bridge into observation-to-insight is noted. State: working · Workspace: core. Stream catalogue: specs/MODEL-MAP.md
